## Executive summary

Four HIGH issues are real and worth acting on this week:

1. A live-looking **Semgrep app token** is tracked in `.env.mcp.example` on a public repo. Revoke it now.
2. **Admin is a one-way latch.** Removing someone from `ADMIN_EMAILS` does not remove `role: "admin"`.
3. **Email fallback** in `getAuthenticatedUser` can bind a JWT to someone else's Convex user (including admin) when `workosId` misses.
4. The **full practice answer key** (2072 `correctIndex` values) is in public git while the API pretends full-mock answers are admin-only.

Four MEDIUM issues: OAuth login CSRF (`state` missing), Convex `deleteAccount` skipping step-up, MCP `@latest` pins, no `CODEOWNERS` on workflows.

No CRITICAL production RCE, SQLi, or unauthenticated Convex admin without a plausible identity-bind path. `npm audit` (high, omit dev) reported **0** vulnerabilities.

## Architecture (Phase 0)

SvelteKit 2 + Svelte 5 on Vercel. Convex backend. WorkOS OAuth (Google / Microsoft). Optional Upstash rate limit (fail-closed in production). Optional Sentry.

Trust boundary that matters: **browser → SvelteKit (cookies, CSP, step-up) → Convex (JWT)**. The Convex URL is public. Any WorkOS JWT can call public Convex functions **without** SvelteKit.

Crown jewels: full question bank, answers, explanations, export.

## Finding 1: Semgrep app token committed in tracked example file — `.env.mcp.example:15`

* **Severity:** HIGH
* **Confidence:** 9/10
* **Status:** VERIFIED
* **Phase:** 2 — Secrets Archaeology
* **Category:** Secrets

**Motivating line:** `SEMGREP_APP_TOKEN=""` holds a 64-character hexadecimal string (not `your_semgrep_app_token`). Token value omitted from this report.

`.gitignore` lines 26–31 ignore `.env.*` then re-include `!.env.mcp.example`. The repo is public.

**Exploit scenario:**
1. Clone the public GitHub repo (or view the file in the browser).
2. Copy `SEMGREP_APP_TOKEN`.
3. Call Semgrep App APIs as that token until it is revoked.

**Impact:** Unauthorized Semgrep org access (findings, scans, metadata; exact scope depends on the token).

**Recommendation:** Revoke in Semgrep now. Replace the tracked value with a placeholder. Keep secrets in `.env.mcp.local` only.

**Incident playbook:**
1. Revoke the credential in Semgrep.
2. Rotate: issue a new token into gitignored local env.
3. Scrub: placeholder in `.env.mcp.example`; history rewrite only if you need the old blob gone.
4. Force-push cleaned history only with a coordinated rewrite plan (public forks retain the old blob).
5. Audit exposure from commit `137c49a` (file added) to revoke time.
6. Review Semgrep audit logs for unexpected use.

## Finding 2: Admin role is sticky — `src/convex/auth.ts:57`

* **Severity:** HIGH
* **Confidence:** 9/10
* **Status:** VERIFIED
* **Phase:** 9 — OWASP A01
* **Category:** OWASP A01

**Motivating lines:**

```
// Promote allowlisted emails; never downgrade admins on profile sync.
if (!isAdminUser(existing) && isAdminEmail(email)) {
  patch.role = "admin";
}
```

**Exploit scenario:**
1. `admin@org` is on `ADMIN_EMAILS`, logs in, `role` becomes `admin`.
2. Operator removes that email from Convex `ADMIN_EMAILS`.
3. User logs in again. Patch does not set `role` to `user`.
4. `requireAdmin` still passes. Full bank list/grade/export remain available.

**Impact:** Offboarded admins keep the answer key forever.

**Recommendation:** Set `role` from the current allowlist on every sync, or add an explicit revoke mutation and run it when the list changes.

## Finding 3: Email fallback in `getAuthenticatedUser` — `src/convex/lib/authorization.ts:37`

* **Severity:** HIGH
* **Confidence:** 8/10
* **Status:** VERIFIED
* **Phase:** 9 — OWASP A01
* **Category:** OWASP A01

**Motivating lines:**

```
if (!user && identity.email) {
  user = await ctx.db
    .query("users")
    .withIndex("by_email", (q) => q.eq("email", identity.email!))
    .unique();
}
```

Website login usually calls `createOrUpdateUser` first (workosId only), which creates the caller's own row and blocks this path. Direct Convex clients can skip that mutation. `by_email` is not a unique schema constraint. `requireAdmin` uses this helper.

**Exploit scenario:**
1. Admin Convex row still stores email `E`; `workosId` no longer matches a new identity that presents `E` (stale email, IdP reuse after an email change).
2. Attacker obtains a WorkOS JWT whose `email` is `E`.
3. Attacker calls Convex with that JWT and **does not** call `createOrUpdateUser`.
4. Lookup by workosId misses; email fallback returns the admin row.
5. Full-mode list/grade and export succeed.

**Impact:** Cross-account bind, including admin, without matching WorkOS subject.

**Recommendation:** Match `workosId` only. Handle email changes with an explicit verified patch. Make email unique.

## Finding 4: Full answer key in public git — `src/convex/seed/devQuestionBank.ts:18`

* **Severity:** HIGH
* **Confidence:** 9/10
* **Status:** VERIFIED
* **Phase:** 2 — Secrets Archaeology / A02
* **Category:** OWASP A02

**Motivating line:** `"correctIndex": 2` on question 0, and 2072 `correctIndex` fields in the same tracked file. License is MIT; GitHub visibility is public. Convex still `requireAdmin`s full mode and strips answers on list.

**Exploit scenario:**
1. `git clone` the public repo.
2. Parse `devQuestionBank.ts`.
3. Read every answer and explanation. No login.

**Impact:** Admin-only full mock on the API does not protect the bank. Anyone with git has the key.

**Recommendation:** If the bank is private IP, stop shipping it in git, load from a private seed path, and purge history. If answers are meant to be public, drop the admin secrecy story and say so in the product.

## Finding 5: OAuth login omits CSRF `state` — `src/lib/workos.server.ts:57`

* **Severity:** MEDIUM
* **Confidence:** 8/10
* **Status:** VERIFIED
* **Phase:** 9 — OWASP A01
* **Category:** OWASP A01

**Motivating lines:** `getOAuthAuthorizationUrl` builds the URL with `clientId`, `provider`, `redirectUri` only. Callback `authenticateWithCode({ code, clientId })` does not check `state`. Step-up helper already has a `state` option.

**Exploit scenario:** Classic login CSRF. Victim completes an attacker-started OAuth code in their browser. Session cookies become the attacker user. Later practice writes to the attacker account.

**Impact:** Session confusion / progress written to the wrong user. No payments in this app.

**Recommendation:** httpOnly CSRF `state` (and PKCE if WorkOS supports it for this flow). Verify on callback.

## Finding 6: `deleteAccount` skips step-up — `src/convex/auth.ts:141`

* **Severity:** MEDIUM
* **Confidence:** 9/10
* **Status:** VERIFIED
* **Phase:** 9 — OWASP A01
* **Category:** OWASP A01

**Motivating contrast:**
- HTTP: `src/routes/api/account/delete/+server.ts` lines 28–37 — `isRecentAuthentication` then Convex.
- Convex: `deleteAccount` lines 141–160 — `getAuthenticatedUser` only.

**Exploit scenario:** Stolen but not-recent WorkOS access token. Website delete returns 403. `ConvexHttpClient.setAuth(token)` + `api.auth.deleteAccount` still wipes the user and progress.

**Impact:** Account destruction without re-auth. Requires a valid access token.

**Recommendation:** Enforce `auth_time` (or a step-up flag) **inside** the Convex mutation.
